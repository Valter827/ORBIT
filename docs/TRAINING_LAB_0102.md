# Training Lab implementation and acceptance

Source provenance: freshly extracted ORBIT-0.10.1-source-20261010.zip, SHA256 A21724C76E09ADD1E2096FE352212FAD5B41066E5B099EE1791F98F5A7AAE80E. Evidence ZIP was not used as source. COSMO remains 1.0; app version 0.10.2.

The local backend is an ORBIT-owned Python subprocess using Transformers/PEFT. It is a separate environment/process, not an OS security sandbox. No private application stores are connected. The worker receives only controlled train/validation rows; final held-out answers stay in the parent evaluator. Network-offline flags, no remote-code loading, safetensors-only model loading, a scrubbed environment and parent-pipe lifetime guard limit accidental access and orphan training. User-controlled Python installation is trusted local software, not an arbitrary imported adapter executable.

Supported workflow: save dedicated local storage, probe an existing isolated CUDA environment, create immutable draft, start a bounded pilot, stop, retain failed-run metadata, register a hash-verified saved/load-tested adapter, run repeated same-prompt base/adapter evaluations, reject inadequate results, export adapter/config/provenance, explicitly confirm deletion of registered adapter files. Pause/checkpoint resume, cloud training, teacher distillation, adapter import, DPO/ORPO and automatic Ollama deployment are NOT IMPLEMENTED. No fake controls advertise those capabilities.

Training-only resources are not bundled with ORBIT: PyTorch and original base weights require explicit provisioning. The installer includes only the small worker script, not Python/CUDA or model weights. Existing Ollama weights remain untouched. D: paths are configurable; no automatic model relocation occurs.

The pilot dataset has 28 train, 14 validation and 14 held-out authored examples. It covers reasoning, JS/TS/Python/Rust semantics, supplied Memory facts, evidence/citations, context priority, RU/UK/EN, JSON, hallucination resistance, conflicts, tool-schema selection, injection and style. It is a small pipeline pilot, not a comprehensive general-model curriculum. Exact prose reference matching is deliberately narrow and can reject valid paraphrases. No broad language-quality claim follows from its score. Exact/near token overlap plus scenario-family separation detects common contamination, not all semantic paraphrases. Dataset checks also compare against all existing baselineCases. Original 0.10.1 benchmark answers are never training data.

Promotion screen: collapse repeated outputs into independent-item differences; mean improvement must exceed an approximate paired 95% uncertainty interval. At least 30 independent held-out items, repeated runs, complete identities, no Memory/Knowledge/security loss and <=1.5x aggregate generation latency are required. This pilot's 14 held-out items cannot pass the general promotion gate. Runtime deployment, actual Memory/Knowledge, vision and tool regressions remain additional mandatory gates. This release fails closed and never assigns Alpha automatically. A future expanded validated dataset and deployment integration are required before general Alpha promotion.

Validation loss selects a bounded best checkpoint; at most two checkpoint directories are retained. maxSteps is the hard optimizer-step budget and takes precedence over epochs in Transformers. Generated adapter weights are separate from base weights and are never merged automatically. Cancellation marks CANCELLED, requests cooperative stop, then terminates the direct worker; checkpoint resume is not promised. Parent closure terminates orphan work.

Real regressions: controlled production-core Memory on explicitly pinned gemma3:4b, Knowledge and public Internet/YouTube. An earlier legacy Memory runner only set modelId but left automatic routing enabled; evidence shows DeepSeek was actually selected. That failed run is retained separately, not relabelled as a Gemma failure or erased. Native Windows UI acceptance is separate from browser/core acceptance.
